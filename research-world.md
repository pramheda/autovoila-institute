# Research World and Representation

## 1. Canonical representation

The canonical research representation is the complete navigable workspace.

It includes:

- institute-level state;
- branch-level state;
- missions;
- literature;
- raw sources;
- hypotheses;
- code;
- data;
- prompts;
- model versions;
- experiments;
- failures;
- outputs;
- disagreements;
- decisions;
- human interventions;
- and confirmation packages.

No single summary is canonical.

## 2. Semantic zoom

A human or agent should be able to move between levels.

### Institute level

- current question;
- active programmes;
- major evidence;
- disagreements;
- resource allocation;
- human decisions.

### Branch level

- local purpose;
- live hypotheses;
- experiments;
- recent changes;
- blockers;
- next actions.

### Experiment level

- exact protocol;
- implementation;
- data;
- results;
- analysis;
- deviations.

### Execution level

- commands;
- logs;
- tool calls;
- files;
- model outputs;
- checkpoints.

Higher levels may compress lower-level detail.

The human must be able to trace important claims downward.

## 3. Views are generated artifacts

Possible views include:

- executive briefing;
- scientific synthesis;
- adversarial review;
- replication package;
- experiment timeline;
- literature map;
- technical audit;
- paper;
- interactive website;
- or context package for a new agent.

Views may be regenerated.

Evidence should not be rewritten to fit the view.

## 4. Current understanding versus history

Maintain both:

- a current compressed state;
- and the historical path that produced it.

Do not require every agent to read the full history.

Do not destroy history merely because it is no longer current.

## 5. Branching and merging

Branch cheaply when:

- hypotheses are meaningfully different;
- independence matters;
- work can proceed in parallel;
- or forcing one representation would lose information.

Merge carefully.

A merge should preserve:

- minority views;
- unresolved contradictions;
- provenance;
- and different predictions.

Do not merge merely to simplify the directory tree.

## 6. Searchability

Use names, indexes, links, and summaries so that a new agent can locate:

- current state;
- relevant evidence;
- active experiments;
- branch relationships;
- and human decisions.

Do not impose a universal ontology before the research demands one.

## 7. Provenance standard

Every important conclusion should be able to answer:

- Which evidence supports it?
- Which branch produced the evidence?
- Which code and data created it?
- Which model and prompt were used?
- Which interpretations disagree?
- What changed the conclusion?
- Did a human intervene?
- Is the result exploratory or confirmatory?
